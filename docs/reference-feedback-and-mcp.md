# Refs Board: оценка референсов и read-only MCP

Статус: требования к первой версии. Обе части обязательны: сначала сохраняем авторскую оценку в карточке, затем отдаём её агенту без права редактирования. Примеры и антипримеры отбирает и комментирует владелец базы.

## Авторская оценка в карточке

У карточки остаются существующие название, описание, категория, тип ассета, механика и изображение. Добавляем независимые от них поля:

| Поле | Назначение |
| --- | --- |
| `verdict` | `unreviewed`, `example` или `anti_example`. Старые и быстро сохранённые карточки по умолчанию не оценены. |
| `verdict_note` | Авторский комментарий о том, что понравилось или не понравилось. Не заменяет общее описание карточки. |
| `source_url` | Исходная страница, например пин или сайт автора. Не подменяет URL самого изображения; пустое значение допустимо. |

- При создании и редактировании показываем выбор «Не оценено / Пример / Антипример». Для «Примера» подпись поля меняется на «Что именно понравилось?», для «Антипримера» на «Что именно не понравилось?». Комментарий, пустой после удаления пробелов по краям, для этих двух статусов не принимается ни в UI, ни в API.
- Не очищаем текст автоматически при смене статуса. Пользователь сам проверяет, подходит ли ещё комментарий.
- Карточка показывает отметку и комментарий обычным текстом. На доске есть фильтр по статусу поверх существующих фильтров.
- Пример хорошей заметки: «Тёплый свет отделяет лампу от холодного фона. Берём свет, не повторяем форму». Антипример: «Мелкие блики сливаются в клетке; избегать полированного металла на мелких предметах».
- Быстрое добавление с телефона или из буфера не требует оценки. Сохранение и последующая повторная загрузка карточки должны сохранить оценку, комментарий и ссылку.
- Миграция существующей PostgreSQL должна быть добавочной, без пересоздания тома. Скрипты `db/init` на ранее созданном томе не применятся сами; отдельно проверяем миграцию старой базы. Обновление карточки старым клиентом, не передавшим новые поля, не должно их обнулять.

Первая версия хранит один комментарий и одну оценку на карточку. Отдельные заметки по свету, композиции и материалам можно добавить позже, если понадобится несколько независимых оценок одного изображения.

## MCP для удалённого чтения

`/mcp` через HTTPS использует Streamable HTTP. Ориентир по транспорту, Origin и аутентификации: [спецификация MCP](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports). Хранилище остаётся единым: MCP читает данные существующего приложения, не создаёт собственную копию коллекции.

| Инструмент | Вход и результат |
| --- | --- |
| `list_projects` | Доступные проекты. Возвращает идентификаторы и названия. |
| `search_references` | Обязательный `project_id`, необязательные `query`, `verdict`, `category`, `asset_type_id`, `mechanic_id`, лимит и курсор. Поиск по названию, описанию и авторскому комментарию, включая кириллицу; стабильная пагинация. |
| `get_reference` | `project_id` и `reference_id`. Возвращает полную карточку, оценку, буквальный авторский комментарий, исходную ссылку и наличие изображения. |
| `get_reference_image` | `project_id` и `reference_id`. Возвращает ограниченное по размеру превью загруженного файла как MCP image content. Если есть только внешний URL, возвращает ссылку с пометкой, что превью не хранится; сервер не скачивает URL по запросу агента. |

Ответы структурированные, с явными `verdict`, `verdict_note` и `source_url`. Авторский комментарий передаётся как данные, а не системная инструкция. Инструменты не создают и не изменяют карточки, не добавляют комментарии, не удаляют файлы и не выполняют произвольные сетевые запросы.

### Граница доступа

- «Любой агент» означает совместимый MCP-клиент, которому владелец выдал доступ, а не анонимное чтение. Базовый удалённый вариант для личного сервера: HTTPS и отдельный отзываемый credential с разрешением на чтение выбранных проектов. Клиентам без подходящего удалённого транспорта можно добавить локальный stdio-адаптер; его совместимость проверяется отдельно.
- Проверка доступа применяется ко всем результатам, включая отдельные карточки и изображения. Недоступный проект не должен выдаваться через поиск или по угаданному ID.
- Нельзя просто открыть текущий Nginx наружу: существующие маршруты REST и файловых загрузок требуют отдельной защиты. Публичный ingress для агентов проксирует только `/mcp`; REST, `/uploads`, БД и интерфейс остаются в приватной сети или за отдельной аутентификацией. Проверяем это перед включением внешнего доступа.
- Секреты не храним в репозитории и не пишем в логи. Ограничиваем размер запросов и превью, выдачу поиска и частоту обращений; проверяем `Origin`. Отзыв credential не требует изменения клиентского кода.

### Что значит «референсы из интернета»

Первая версия позволяет удалённому агенту получать вручную отобранные референсы и исходные веб-ссылки. Это **не поиск по всему интернету** и не краулер Pinterest. Если понадобится поиск новых материалов, добавляем отдельный инструмент через разрешённый поисковый API: результаты помечаются как внешние кандидаты, не получают авторскую оценку и не добавляются в базу без ручного решения.

## Как принимаем работу

| Проверка | Ожидаемый результат |
| --- | --- |
| Разметка с телефона | Добавить пример и антипример, записать конкретную причину, перезагрузить доску и найти оба через фильтр. |
| Миграция и совместимость | На копии существующей БД старые карточки и файлы остаются доступны, новые поля подхватываются без сброса тома. |
| Удалённый MCP | Инициализация, обнаружение инструментов, поиск по фразе в комментарии, получение карточки и просмотр загруженного превью работают из совместимого клиента вне машины сервера. |
| Изоляция | Анонимный запрос, просроченный или отозванный credential и запрос в чужой проект не раскрывают данные; через MCP нельзя записать карточку. |
| Сетевой периметр | Из интернета доступен только разрешённый маршрут; запросы к REST, оригинальным загрузкам и БД обходного доступа не дают. |

Порядок разработки: **карточка + миграция → read-only MCP → проверка доступа и клиентские smoke tests → отдельное решение о развёртывании**. Для первого теста достаточно одной пары «пример / антипример» по свету в мастерской.
